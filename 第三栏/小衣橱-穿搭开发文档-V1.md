# 小衣橱｜穿搭开发文档 V1

版本：V1.1（收口版）  
用途：供 Codex「穿搭」子代理独立开发、联调与验收  
页面：底部 Tab「穿搭」  
视觉依据：用户确认的穿搭参考图  
业务依据：`../小衣橱_V1_正式PRD_V1.4.md`、`../小衣橱-三子代理公共接口与开发边界说明-V1.md` 及用户最新确认

---

# 1. 开发优先级

1. 用户确认参考图：视觉、布局、卡片结构最高优先。
2. 本开发文档：交互、进入方式、推荐、保存、编辑规则最高优先。
3. V1.4 正式 PRD：未冲突产品总纲继续保留。

禁止擅自：
- 改变参考图整体结构。
- 将页面改回「AI搭配」或「穿搭平铺」。
- 自动选中历史搭配。
- 自动设置今日穿搭。
- 使用真人试穿、人体模型或生成式服装图片。
- 用五张商品图并排代替叠穿预览。
- 强制覆盖已有搭配或强制另存。

# 7. 叠穿预览规则

固定层级：

```text
hat-layer
top-layer
bottom-layer
shoes-layer
bag-layer
```

要求：

- 帽子在最上方。
- 上衣位于上半身。
- 下装与上衣自然衔接并可轻微重叠。
- 鞋子位于下装下方。
- 包包可覆盖上衣或下装侧边。
- 组合后应看起来像一整套穿搭。
- 图片使用 contain，不裁切主体。

禁止：

- 真人模特。
- 人体轮廓。
- 五张独立商品卡并排。
- 针对某一件衣服写特殊定位补丁。
- 生成新的服装图片。

# 11. 「换一套」定义

用户已确认：

```text
根据当前季节随机推荐一套
风格不限
```

不是历史搭配切换，也不是 AI 生图。

推荐数据只能来自：

```text
当前衣橱中未删除、有效的单品
```

推荐要求：

- 当前季节匹配。
- 风格不限。
- 上衣必须存在。
- 下装必须存在。
- 鞋子必须存在。
- 帽子可无。
- 包包可无。
- 尽量避免与当前组合完全一致。
- 不自动保存。

点击：

```text
换一套
→ 判断当前季节
→ 从该季节有效单品随机组合
→ 更新五槽选中状态
→ 更新顶部预览
→ 不自动保存
```

如当前季节核心单品不足：

```text
当前季节可搭配单品不足
[去衣橱上传]
```

不得伪造推荐。

季节判断必须复用公共 `getCurrentSeason()`：3～5 月春、6～8 月夏、9～11 月秋、12～2 月冬，不允许各子代理各自定义不同月份映射。

# 19. 设为今日穿搭

正确流程：

```text
穿搭详情
→ 点击「设为今日穿搭」
→ 用户确认
→ 保存 todayOutfit = { 当日本地日期, outfitId }
→ 成为当天今日穿搭
```

同一时间最多一个有效今日穿搭。

今日穿搭使用公共单一事实源 `todayOutfit`，不得在 `SavedOutfit` 内额外维护 `isToday`。

跨日规则：

```text
进入下一天
→ 昨日今日穿搭失效
→ 当前视为“没有今日穿搭”
```

小程序启动、回前台或首页读取时按用户设备本地日期校验，无需后台定时器。

禁止从：

- 历史列表卡。
- 首页智能匹配结果卡。
- 换一套结果。

直接自动设置。

# 21. 编辑后的保存方式

用户已确认采用：

```text
更新原搭配
另存为新搭配
取消
```

## 更新原搭配

- 保留原 outfitId。
- 更新五槽。
- 更新名称 / 季节 / 风格。
- 更新预览缩略图。
- 更新 updatedAt。
- 不创建新记录。

如果原搭配是今日穿搭：

```text
更新后今日穿搭同步使用最新内容
```

## 另存为新搭配

- 创建新 outfitId。
- 原搭配不变。
- 当前编辑结果生成新记录。
- 使用新的 createdAt。

# 22. 已删除衣橱单品兼容

历史穿搭中包含已经从衣橱删除的单品：

- 历史详情继续显示保存时快照；快照图片仍被引用时，底层云端文件不得被物理删除。
- 新搭配候选不再出现该单品。

进入编辑后，对应槽位提示：

```text
该单品已从衣橱删除，请重新选择对应单品
```

必须重新选择有效单品后，该槽位才能正常保存更新。

该规则必须与《衣橱开发文档》一致。

# 24. 状态模型建议

```ts
type OutfitDraft = {
  sourceOutfitId?: string | null

  slots: {
    hat: WardrobeItemRef | null
    top: WardrobeItemRef | null
    bottom: WardrobeItemRef | null
    shoes: WardrobeItemRef | null
    bag: WardrobeItemRef | null
  }

  title: string
  season: 'spring' | 'summer' | 'autumn' | 'winter' | null
  style: 'casual' | 'commute' | 'sweet' | 'cool' | null

  mode: 'create' | 'edit'
  dirty: boolean
}
```

约束：

- 当前五槽是唯一事实来源。
- 不维护重复选择状态。
- 单品改变后 `dirty = true`。
- 编辑已有搭配时保存 `sourceOutfitId`。

# 24.1 草稿保留规则

用户在穿搭主页面产生未保存修改后：

- 普通 Tab 切换不得清空草稿。
- 返回穿搭页继续显示当前选择。
- 首页快速开始只打开历史组合选择，不覆盖草稿。
- 从某套穿搭详情点击「编辑」准备加载另一套时，如果已有未保存草稿，必须先提示用户是否替换。
- 用户取消替换时保留原草稿。

保存成功后将当前草稿标记为已保存 / `dirty = false`。

# 25. 保存数据结构建议

```ts
type SavedOutfit = {
  id: string
  createdAt: string
  updatedAt: string

  title: string
  season: 'spring' | 'summer' | 'autumn' | 'winter'
  style: 'casual' | 'commute' | 'sweet' | 'cool'

  items: {
    hat: OutfitItemSnapshot | null
    top: OutfitItemSnapshot
    bottom: OutfitItemSnapshot
    shoes: OutfitItemSnapshot
    bag: OutfitItemSnapshot | null
  }

  previewImageUrl?: string
  previewFileId?: string
}
```

结构化 `items` 是主数据，缩略图只用于展示。

每个槽位应保留必要快照，以兼容衣橱单品删除。

# 26. 与衣橱子代理边界

穿搭新组合和「换一套」只读取：


# 27. 与首页子代理边界

穿搭必须保证：

- 新保存搭配后首页最近保存可刷新。
- 设置今日穿搭后首页第一栏可刷新。
- 保存季节 / 风格可供首页智能筛选。
- 首页快速开始可进入历史搭配选择。
- 「去搭配单品」可进入穿搭主页面。
- 首页和我的搭配都能使用统一 outfitId 打开详情。
