# 小衣橱｜首页开发文档

版本：V1.1（收口版）  
用途：供 Codex 首页子代理独立开发与验收  
页面：底部 Tab「首页」  
视觉依据：用户确认的首页设计图  
业务依据：`../小衣橱_V1_正式PRD_V1.4.md`、`../小衣橱-三子代理公共接口与开发边界说明-V1.md` 及用户最新确认规则

---

# 1. 文档目的

本文件只定义「首页」的布局、交互、数据关系、页面映射和验收标准。

开发时遵循以下优先级：

1. 用户确认的首页设计图：视觉、布局、模块顺序的最高依据。
2. 本开发文档：交互、页面映射、状态和业务规则的最高依据。
3. 现有 PRD：未与前两项冲突的内容继续保留。

禁止首页子代理擅自：
- 改变设计图中的整体结构、模块顺序、主色、卡片形态。
- 新增设计图中不存在的大型模块。
- 将“智能穿搭建议”改成 AI 临时生成穿搭。
- 自动替用户选中或确认某套穿搭。
- 修改衣橱、穿搭页面内部业务，只能按本文约定跳转。

---

# 2. 首页用户需求

首页的核心需求不是自动替用户做决定，而是完成以下 4 件事：

1. 快速进入穿搭流程。
2. 查看当前位置的天气及基础穿搭建议。
3. 快速回看最近保存的穿搭。
4. 按季节和风格，从用户已经保存过的穿搭中筛选适合当前需求的组合。

首页不得临时从衣橱自动生成新的穿搭。

---

# 3. 页面整体布局

首页保持设计图中的粉白色、轻柔圆角卡片视觉。

页面纵向从上到下固定为：

```text
顶部标题区
↓
栏目 1：今日搭配启动卡
↓
栏目 2：天气建议
↓
栏目 3：最近保存穿搭
↓
栏目 4：智能穿搭建议
↓
底部固定 TabBar
```

不得调整四个业务栏目的先后顺序。

---

# 4. 顶部标题区

## 4.1 布局

左侧：

```text
小衣橱 ✦
今日穿搭灵感
```

右侧：

- 圆形用户头像。

视觉要求：

- 标题使用设计图中的粉色高强调样式。
- 副标题为深灰色弱一级文本。
- 头像位于右上角，尺寸、圆形描边、留白关系按设计图实现。
- 不额外增加搜索、通知、设置等图标。

## 4.2 操作

点击头像：

```text
首页
→ 个人中心
```

个人中心为独立页面。

首页子代理只负责正确跳转，不负责擅自设计个人中心内部内容。

# 5. 栏目 1：今日搭配启动卡

## 5.1 页面定位

该卡片是首页最主要的穿搭入口。

视觉结构严格参考设计图：

左侧：
- 日期。
- 主标题「开始今天的搭配」。
- 辅助文案「从你的衣橱中挑选一套今天想穿的搭配」。
- 主按钮「快速开始搭配」。

中间：
- 一套穿搭组合平铺预览图。

右侧：
- 天气图标。
- 当前温度。
- 天气状态。
- 当前城市。

## 5.2 删除设计稿中的无效轮播圆点

设计图底部存在 3 个轮播圆点。

本轮用户已确认：

```text
不代表任何业务功能。
正式开发删除。
```

不得为了保留视觉而实现无业务意义的假轮播。

## 5.3 「快速开始搭配」操作流

点击：

```text
快速开始搭配
↓
进入「穿搭」栏目
↓
首先只展示用户以前已经搭配过并保存过的穿搭组合
↓
不自动选中任何一套
↓
由用户自己查看、选择
```

关键约束：

- 不自动加载上一次穿搭。
- 不自动选中第一套。
- 不直接进入五类单品选择状态。
- 首屏只展示用户曾经搭配过的组合。
- 用户需要主动选择某套组合。

如果用户对历史组合都不满意：

```text
点击进入单品搭配的按钮
↓
进入穿搭页面的五类单品选择区域
↓
用户自行重新搭配
```

该按钮文案固定为：

`去搭配单品`

点击后进入穿搭页面的五类单品选择区域。

首页子代理不得修改该文案的业务含义，也不得新增其他跳转分支。

## 5.4 无历史穿搭时

如果用户从未保存过穿搭：

```text
快速开始搭配
↓
进入穿搭栏目
↓
显示“暂无历史搭配”空状态
↓
提供进入五类单品搭配的按钮
```

不得展示伪造示例穿搭作为用户历史记录。

# 6. 栏目 2：天气建议

## 6.1 布局

保持设计图的单张横向圆角卡片。

左侧：
- 天气图标。

中间：
- 标题「天气建议」。
- 当前天气。
- 温度区间。
- 一句基础穿搭建议。

右侧：
- 线性衣服装饰图标。

示例结构：

```text
☀  天气建议
    晴天，气温 20~29℃
    适合轻薄透气的穿搭，防晒别忘了～
```

## 6.2 城市与定位

首页第一栏右侧显示当前城市，例如：

```text
上海
```

点击城市后：

```text
点击当前城市
↓
打开城市/定位选择
↓
支持：
  1. 重新获取当前位置
  2. 手动搜索并选择城市
↓
用户确认城市
↓
更新定位城市
↓
重新请求该城市天气
↓
同步更新首页所有天气相关信息
```

## 6.3 城市切换后的同步范围

城市改变后必须同时更新：

- 第一栏右侧当前城市。
- 第一栏当前温度。
- 第一栏天气状态。
- 第一栏天气图标。
- 天气建议栏天气状态。
- 天气建议栏温度区间。
- 天气建议文案。

禁止出现：

```text
城市已经改为北京
但温度和建议仍然显示上海数据
```

## 6.4 定位与天气异常

### 定位失败

- 不阻塞首页其他模块。
- 提供重新定位。
- 允许用户手动搜索城市。

### 天气请求失败

- 保留当前已选择城市。
- 天气区域显示加载失败状态。
- 提供重试。
- 最近穿搭、智能穿搭等其他模块仍可正常使用。

# 7. 栏目 3：最近保存穿搭

## 7.1 布局

标题行：

左侧：

```text
最近保存穿搭
```

右侧：

```text
全部 >
```

下方：

- 按设计图横向展示最近 4 套。
- 每张卡片保持窄长圆角卡片形态。
- 上方为完整穿搭平铺缩略图。
- 下方为穿搭名称。
- 最下方为保存日期。

示例：

```text
清新甜美风
07-12
```

## 7.2 数据排序

按保存时间倒序：

```text
最新保存
→ 最先展示
```

首页最多展示设计图对应的 4 套。

不足 4 套时按实际数量展示，不造假数据。

## 7.3 点击单张穿搭

用户已确认：

```text
点击最近保存穿搭卡
↓
进入该套穿搭详情
```

详情页中再提供后续动作。

不得：

- 点击卡片直接进入编辑状态。
- 点击卡片直接修改原记录。
- 点击卡片自动设为今日穿搭。

## 7.4 点击「全部」

```text
首页
→ 最近保存穿搭
→ 全部
→ 我的搭配列表
```

列表页展示所有已保存穿搭。

首页子代理只负责入口和数据调用，不负责擅自重做列表页内部布局。

## 7.5 空状态

用户没有任何已保存穿搭时：

- 不展示假卡片。
- 显示简洁空状态。
- 提供进入穿搭流程的入口。

入口行为必须遵循第 5 章定义的穿搭流程。

# 8. 栏目 4：智能穿搭建议

## 8.1 产品定义

该栏目不是 AI 自动生成穿搭。

定义为：

```text
根据用户选择的季节和风格
从用户“已经保存过的穿搭”中筛选匹配结果
```

不得从衣橱临时组合一套新穿搭。

## 8.2 布局

保持设计图的大圆角卡片。

顶部：
- 标题「智能穿搭建议 ✦」。
- 辅助说明。
- 右侧衣架/衣服装饰图。

中部两行筛选：

第一行：

```text
季节  春  夏  秋  冬
```

第二行：

```text
风格  不限  休闲  通勤  甜美  潮酷
```

底部右侧：

```text
查看匹配穿搭 →
```

## 8.3 季节规则

季节为单选。

可选：

```text
春
夏
秋
冬
```

任何时刻最多选中一个季节。

## 8.4 风格规则

风格为单选。

可选：

```text
不限
休闲
通勤
甜美
潮酷
```

「不限」仅表示：

```text
不限风格
```

不代表：
- 不限季节。
- 清除全部筛选条件。
- 保存记录中的一个真实风格值。

## 8.4.1 默认筛选状态

首页没有已保存筛选状态时默认：

```text
季节：当前季节
风格：不限
```

当前季节统一调用公共 `getCurrentSeason()`：3～5 月春、6～8 月夏、9～11 月秋、12～2 月冬。

## 8.5 查看匹配穿搭操作流

```text
选择一个季节
↓
选择一个风格
↓
点击「查看匹配穿搭」
↓
进入独立「匹配穿搭」结果页
↓
查询用户已保存穿搭
↓
展示全部符合条件的结果
```

匹配结果不是只返回 1 套。

## 8.6 匹配结果页操作规则

匹配结果列表页：

- 展示多套符合条件的已保存穿搭。
- 用户点击其中一套后进入该套穿搭详情。

禁止在结果列表卡片上直接完成：
- 设为今日穿搭。
- 编辑原穿搭。
- 自动加载到穿搭页。

正确流程：

```text
匹配结果列表
↓
点击某套穿搭
↓
穿搭详情
```

## 8.7 穿搭详情中的两个主要动作

### 动作 A：设为今日穿搭

用户已确认：

```text
匹配结果
↓
穿搭详情
↓
用户确认
↓
设为今日穿搭
↓
保存成功
↓
该套成为“今日穿搭”
```

必须由用户主动确认。

不得因为匹配成功就自动设置。

### 动作 B：继续修改

正确流程：

```text
匹配结果
↓
穿搭详情
↓
点击「编辑」
↓
将该套搭配加载到穿搭页面
↓
用户自行修改
```

关键约束：

- 允许加载到穿搭页修改。
- 但必须进一步点击「编辑」。
- 不能点击匹配结果卡后直接进入编辑模式。

## 8.8 无匹配结果

显示：

```text
没有找到符合当前季节和风格的穿搭
```

用户可以：

- 返回修改季节。
- 返回修改风格。
- 前往穿搭栏目重新搭配并保存。

不得临时自动生成一套穿搭填补结果。

# 9. 首页「今日穿搭」数据关系

首页需要区分以下概念：

```text
已保存穿搭
历史搭配
匹配结果
今日穿搭
正在编辑的穿搭
```

它们不是同一个状态。

## 9.1 已保存穿搭

用户已经确认保存的穿搭记录。

首页最近保存和智能匹配都基于它。

## 9.2 历史搭配

供“快速开始搭配”进入穿搭页后首先查看的已保存组合。

不自动选中。

## 9.3 匹配结果

由：

```text
季节 + 风格
```

从已保存穿搭中过滤得到。

匹配本身不会改变任何记录状态。

## 9.4 今日穿搭

只有用户在穿搭详情中主动确认后，才能设置。

统一读取公共单一事实源：

```ts
todayOutfit: {
  date: string
  outfitId: string
} | null
```

其中 `date` 为用户设备本地日期 `YYYY-MM-DD`。

跨日规则：

```text
进入下一天
→ 昨日记录失效
→ 首页显示“没有今日穿搭”
```

首页加载 / 回到前台时比较保存日期和当前本地日期，不同则清空或按空状态处理。

不得在 `SavedOutfit` 上再维护 `isToday` 形成第二事实源。

## 9.5 编辑中的穿搭

从详情页点击「编辑」后加载到穿搭页的临时编辑状态。

修改过程中不得直接覆盖原保存记录，最终保存方式由穿搭开发文档统一定义。

# 11. 首页数据要求

首页至少需要以下语义数据：

```ts
type HomePageData = {
  user: {
    avatarUrl: string | null
  }

  location: {
    cityName: string
    latitude?: number
    longitude?: number
    source: 'device' | 'manual'
  }

  weather: {
    condition: string
    currentTemp: number | null
    minTemp: number | null
    maxTemp: number | null
    icon: string | null
    outfitAdvice: string | null
  }

  todayOutfit: {
    assignment: { date: string; outfitId: string } | null
    outfit: OutfitSummary | null
  }

  recentOutfits: OutfitSummary[]

  filters: {
    season: 'spring' | 'summer' | 'autumn' | 'winter'
    style: 'all' | 'casual' | 'commute' | 'sweet' | 'cool'
  }
}
```

具体数据库字段名由主代理结合现有工程统一，不要求首页子代理擅自重构数据库。

# 12. 与其他并发子代理的边界

## 首页子代理负责

- 首页布局。
- 首页四栏 UI。
- 首页数据读取。
- 首页筛选条件。
- 首页城市切换入口。
- 天气数据同步展示。
- 正确触发页面跳转。
- 首页加载/空/错状态。

## 首页子代理不负责

- 衣橱上传和单品管理实现。
- 穿搭页面五类单品选择内部实现。
- 穿搭详情页完整编辑器实现。
- 个人中心内部功能设计。
- 我的搭配列表页的视觉重构。
- 自行修改公共数据库结构。

若其他页面尚未完成，可保留正式路由接口，但不得用假业务永久替代。

# 13. 视觉开发限制

首页必须贴近提供的设计图。

重点保持：

- 粉白背景。
- 粉色强调色。
- 大圆角。
- 细边框。
- 柔和阴影。
- 卡片间足够留白。
- 首页第一栏最大、天气栏较矮、最近穿搭横向卡片、智能建议大卡片。
- 底部 TabBar 的位置和整体视觉比例。

禁止：

- 改成深色主题。
- 改成 Material Design 风格。
- 大面积渐变替代原图。
- 为“优化”而重排栏目。
- 把最近穿搭改成纵向列表。
- 把筛选改成下拉框。
- 把季节或风格改成多选。
- 恢复已经确认删除的轮播圆点。
- 随意增加悬浮按钮。

---

# 14. 首页加载状态

进入首页后，各模块应独立加载。

不得因为天气接口慢导致：

- 最近穿搭不显示。
- 智能筛选不可用。
- 整个页面白屏。

建议模块级状态：

```text
用户信息
天气
今日穿搭
最近保存穿搭
```

分别处理。

---

# 15. 首页刷新规则

重新进入首页或用户主动刷新时：

需要重新读取：

- 当前用户信息。
- 当前选定城市。
- 天气数据。
- 今日穿搭。
- 最近保存穿搭。

从穿搭详情成功设置“今日穿搭”后返回首页：

- 第一栏必须显示最新今日穿搭。
- 不允许继续显示旧缓存。

从穿搭页新保存穿搭后返回首页：

- 最近保存穿搭必须能够刷新并显示最新记录。

# 16. 首页验收标准

只有全部满足才能认为首页开发完成。

## 16.1 视觉

- [ ] 页面整体结构与用户首页设计图一致。
- [ ] 四个业务栏目顺序完全一致。
- [ ] 第一栏保持设计图中的大卡结构。
- [ ] 天气建议保持横向卡片。
- [ ] 最近保存穿搭保持横向 4 卡布局。
- [ ] 智能建议保持季节、风格两行胶囊选择。

# 17. 已确认入口文案

穿搭页在“历史组合都不满意”时进入五类单品搭配区域的按钮固定为：

```text
去搭配单品
```

操作：

```text
点击「去搭配单品」
→ 进入五类单品选择区域
→ 用户自行选择帽子 / 上衣 / 下装 / 鞋子 / 包包
```

不得改成直接自动选衣或自动生成搭配。

# 18. 首页开发完成定义

首页开发完成必须同时满足：

```text
设计图布局基本复刻
+
四个栏目业务完整
+
所有点击映射正确
+
天气与城市联动正确
+
最近保存数据正确
+
智能筛选只使用已保存穿搭
+
匹配结果不替用户做决定
+
今日穿搭必须由用户主动确认
+
与衣橱/穿搭并发开发边界清晰
```

不满足其中任意一项，不应宣布首页开发完成。
